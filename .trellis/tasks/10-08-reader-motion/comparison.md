# QReader 与 Qiaomu Reader 功能对照及改进建议

日期：2026-10-08。

**结论：Qiaomu Reader 的通用阅读工具和 AI 工作区更完整；QReader 已有可继续发展的听读、生词淡化与笔记合并能力。建议先补齐书内查找和精确回看，再把“读、听、理解、留下自己的笔记”做得更连贯。** 以下优先级是后续建议，本轮已完成的功能为连续翻页和快速开书。

**本轮交付与对照范围**

- QReader 已推送远程 main 并发布正式 [1.2.6 Release](https://github.com/lulalulaluobo/QReader/releases/tag/1.2.6)。源码提交 `f99e8bb1a598e6a0b1a73b81599fdadef059566d`，注解标签 `1.2.6` 指向该提交。公开四附件的下载字节、SHA-256 和 GitHub digest 一致；ZIP 精确三个插件文件。后续报告提交只更新文档。
- 参考项目重新克隆于 `references/qiaomu-reader-20261008`，默认分支为 `efbc811c6decd7bb9034b084f366ec6950321320`；再次检查远程 HEAD 未变。manifest 与[最新正式 Release](https://github.com/joeseesun/qiaomu-reader/releases/tag/4.5.14)均为 **4.5.14**。README 截图注明 4.2.4，未将截图版本当作当前版本。
- 功能判断以双方当前代码、设置和命令入口为主。QReader 完成独立 Obsidian 六格式验收；参考项目完成代码对照，本轮未安装运行它做相同计时或真机测试。“未发现”指当前代码没有对应内置入口，不代表 Obsidian 不能通过其他插件实现。
- 每章三问、复习任务和思考线已从 QReader 撤下；只保留历史兼容，不作为当前功能计算。后续建议也不默认恢复这些流程。

**这次性能问题的原因与实际改动**

流畅翻页的关键是相邻两页同时存在，并连续改变其位置。QReader 原来的跨章流程先清掉旧章节，再加载新章节；现在同章移动既有内容列，跨章先准备真实相邻 iframe，PDF 先渲染目标画布，滑动结束才回收旧页。手动横向翻页使用 300ms ease-out，并遵循系统减少动态效果设置。朗读定位和恢复位置维持直接导航，避免每句朗读额外播放翻页动画。[QReader 分页实现](https://github.com/lulalulaluobo/QReader/blob/1.2.6/src/reader/epub-slide-manager.ts)、[PDF 实现](https://github.com/lulalulaluobo/QReader/blob/1.2.6/src/reader/pdf-engine.ts)、[共用动画](https://github.com/lulalulaluobo/QReader/blob/1.2.6/src/reader/page-motion.ts)。

参考项目的自定义分页路径对内容带做 `translate3d`，CSS 为 280ms；但当前 EPUB/MOBI/FB2/CBZ 已使用 Foliate，PDF 仍使用自定义分页。当前 Foliate 适配器未显式设置 `animated` 属性，因此不能把旧分页器的动画代码直接当成最新版 EPUB 的完整解释。此次实现对应用户要求的“两页连续移动”，没有照搬其渲染器。[参考分页代码](https://github.com/joeseesun/qiaomu-reader/blob/efbc811c6decd7bb9034b084f366ec6950321320/src/main.js#L3223)、[CSS](https://github.com/joeseesun/qiaomu-reader/blob/efbc811c6decd7bb9034b084f366ec6950321320/src/styles.css#L879)、[Foliate 适配器](https://github.com/joeseesun/qiaomu-reader/blob/efbc811c6decd7bb9034b084f366ec6950321320/src/reader-engine.js#L112)。

开书延迟的主因是 QReader 在首屏前等待 EPUB.js 全文位置索引。该依赖默认每个线性章节等待 100ms，20 章便累积约两秒。参考项目直接打开当前章节并恢复位置，没有相同的全文索引等待。1.2.6 已改为当前章节先显示、索引后台分章生成，并让词表读取与渲染并行；有效 CFI 直接恢复，只有百分比的旧记录按需等待索引。原定位体系继续保留。[QReader 开书实现](https://github.com/lulalulaluobo/QReader/blob/1.2.6/src/reader/epub-engine.ts)、[后台索引](https://github.com/lulalulaluobo/QReader/blob/1.2.6/src/reader/epub-locations.ts)。

| 同一书籍、同一恢复位置 | 1.2.5 中位数 | 1.2.6 中位数 | 改善 |
| --- | ---: | ---: | ---: |
| 2 章中文 EPUB | 419ms | 141ms | 约 66% |
| 20 章 Alice MOBI | 2436ms | 203ms | 约 92% |

各组三次，使用独立 macOS Obsidian 1.12.4、本地文件、释放书籍缓存后进入；计时从调用开书到完成并等待两帧，实际恢复 CFI 相同。完整数据与边界验证见 [verification.md](./verification.md)。参考项目“100–200ms”仍是用户观察值，本轮没有同机同书的竞品运行数据；不能据此宣布 QReader 全面更快，也不能保证所有书均在 200ms 内打开。

体积也不能单独解释开书速度。公开附件中，QReader 的 main.js 约 6.45MB，参考项目约 4.89MB；参考样式约 3.68MB，QReader 约 0.039MB。两边打包内容不同。本次有效改善来自移除首屏等待、减少重复排版，而非只减少附件大小。

**当前功能差异**

| 功能 | QReader 1.2.6 | Qiaomu Reader 4.5.14 | 对 QReader 的意义 |
| --- | --- | --- | --- |
| 书籍格式 | EPUB、PDF、FB2/FB2.ZIP、未加密 MOBI、AZW3、CBZ | 同六类；另有 `.fbz`、`.azw` 扩展名入口 | 主流格式已接近，不需把扩展名数量作为重点 |
| 书架 | 真封面、每页四书、书名/作者搜索、未读/已读、自定义分类 | 继续阅读、状态/有划线筛选、划线数量、笔记入口、内置六本公版书 | 借鉴继续阅读与首次体验，减少找入口和准备书籍的成本 |
| 导入与找书 | 本地原书导入，存入 Vault | 本地导入、桌面 Calibre 按需复制、Gutenberg 搜索下载、外部书源链接 | Calibre 对已有大量藏书的人有价值；书源聚合优先级较低 |
| 翻页与位置保存 | 单页/滚动，连续横移，自动保存 CFI 或 PDF 页内位置 | 单/双页与滚动，Foliate/自定义 PDF 路径，保存阅读位置 | 本轮已补连续移动；宽屏双页可按需求后续增加 |
| 字体与主题 | 原书/系统无衬线/系统衬线；四种配色与跟随系统 | 内置朱雀仿宋子集、本机字体、导入 TTF/OTF/WOFF；更多主题、设备外观与电子墨水屏设置 | 字体选择值得借鉴；增加主题数量的收益通常低于可读性和稳定性 |
| PDF | 原版式、文字层、选文、高亮、批注、朗读；当前按可用宽度适配 | 原版式、文字层及批注；独立 50%–300% 缩放、缩放快捷键、单/双页 | QReader 缺少用户可控缩放，图表与小字阅读是明显短板 |
| 书内搜索 | 只有书架的书名/作者搜索，没有书内全文搜索入口 | EPUB 引擎搜索、PDF 文字搜索、结果高亮、上一处/下一处、返回原阅读点 | 应优先补齐；阅读中的查找与回看价值很高 |
| 精确导航 | 目录、批注和笔记回到原文 | 目录、命名位置标记、页码/位置/百分比跳转、跳转后返回 | 补“返回刚才的位置”，再考虑独立书签和页码输入 |
| 高亮与批注 | 多色高亮、个人批注、选文菜单、原文定位 | 高亮、批注、右键入口、可配置选文按钮和顺序 | 先保持常用操作简单，按真实需求增加定制 |
| Markdown 阅读笔记 | 每书一份；整书想法自由编辑；按记录三方合并，冲突保留双方文本 | 每书关联专用笔记，划线汇总到托管章节；独立摘录、AI 回答可追加或另存 | 两者都有本地笔记；QReader 的手工修改保护应保留并强化 |
| 笔记同步策略 | 持久合并基线、逐条处理，删除记录仍保留被手改的文字 | 托管划线章节整体替换，另有旧手工摘录迁移和独立章节保护 | 同步机制不同；不能把托管区更新等同于逐条三方合并 |
| 听书 | 从当前可见句或选文起读；暂停/倍速/选声；手动浏览继续播音，进入下一朗读页恢复跟随 | 当前源码、设置和命令中未发现内置听书 | QReader 现有差异优势，但后台与手机播放还需实际验收 |
| 查词与译文 | 免密有道英文词释义、音标和发音；整句经已配置 AI 译为中文 | Google 免费翻译或 AI，单词/短语/句段，多目标语言，上下文词义 | 快速词典保留；可借鉴目标语言和上下文义项，但需控制响应时间 |
| 生词 | 每书自动加入、有效出现计数、逐渐淡化，默认 5 次未查后移除；可手动删除 | 主动收录到 Markdown 生词本，保留原句和回跳，同词补例句 | 两套产品目标不同：阅读中熟悉词汇与长期收藏复习各有用途 |
| 复习生态 | 无背诵、测试或复习任务 | Spaced Repetition 卡片格式；通过 AnkiConnect 可同步到 Anki | 如需要，可增加用户主动导出；不应默认改变现有自动淡化流程 |
| AI 交互 | 选段一次性上下文解释、整句翻译；用户决定是否存入笔记 | 并排多轮对话、流式 Markdown、快捷问题、按书草稿/对话、回答另存或追加 | 参考“来源固定、可取消、明确保存”；不必立即扩成完整聊天工作区 |
| AI 接入与密钥 | DeepSeek、Agnes、自定义 OpenAI 兼容接口；密钥在本地 data.json | 多种 API、本地 Ollama/LM Studio、桌面 CLI/ACP；使用 Obsidian SecretStorage | 密钥存储值得优先改进；接入数量应服从实际使用需求 |
| AI 上下文 | 选文及前后文、书名与章节 | 选文、当前页；文本 PDF 可作为整书上下文，超过 180,000 字符精简 | 借鉴显式来源和发送范围，避免把全文默认发送当作质量保证 |
| 阅读习惯与生态 | 无内置每日计时目标；书架/阅读/笔记默认在当前标签页并支持原生回退 | 阅读计时/每日目标、乔木 Home/Agent 衔接、并排阅读与讨论 | 先优化当前阅读链路；目标计时和外部集成不是必备差距 |
| 语言与安装 | 中文/英文 UI；查词释义与整句译文仍为中文；Release/BRAT，最低 Obsidian 1.5.0 | 九种 UI 语言；社区市场安装，最低 1.11.4 | 社区分发有明显便利；增加语言前先完善已有双语体验 |

**各自的优缺点**

| 项目 | 优点 | 短板或取舍 |
| --- | --- | --- |
| QReader | 听书与手动浏览协调；生词提示随实际阅读淡化；笔记可在原生编辑器自由修改并合并；辅助操作按需出现；本轮首屏与连续翻页已有实测改善 | 书内搜索、独立 PDF 缩放、命名书签等基础工具不足；字体与宽屏布局选择少；大 MOBI/AZW3/FB2/CBZ 每次打开仍有转 EPUB 的成本；查词输出偏中英场景；密钥尚存明文配置；手机真机与后台听书证据不足 |
| Qiaomu Reader | 阅读、查找、定位、字体和 PDF 工具更齐全；多轮 AI 来源与草稿管理完整；生词能衔接现有复习工具；Calibre/公版书和内置示例降低上手门槛；社区市场方便分发 | 当前没有发现内置听书或阅读出现后自动淡化生词；AI 接入、设备外观和外部工具较多，配置与维护成本更高；托管笔记区以重建为主，与自由逐条修改合并的目标不同；最新最低 Obsidian 版本更高 |

“更完整”是功能覆盖判断；“更简单、维护成本较低或较高”是根据入口和依赖数量的产品推断，不能替代真实用户测试。参考项目本身也有独立模块、覆盖多个领域的自动测试、国际化检查和发布包核验脚本，不能仅凭它的 main.js 较长就判断工程质量差。[参考构建与验证脚本](https://github.com/joeseesun/qiaomu-reader/blob/efbc811c6decd7bb9034b084f366ec6950321320/package.json)。

QReader 同样不能只凭几本测试书宣布稳定性优于竞品：这次桌面测试覆盖六格式与异常场景，但未做双方相同大书样本、安卓/iOS 真机、后台播放和大量书架的系统对照。

**可以直接借鉴的设计**

1. **把重工作移出开书关键路径。** 本轮已应用当前章节先显示。下一步分别测文件读取、格式转换、首屏排版、索引和词表，定位真正的长尾。参考项目原生 Foliate 读多格式，值得研究；先做转换缓存通常比全面换引擎更容易保住现有 CFI 和批注。
2. **临时查找必须能返回。** 搜索、跳页、脚注、回看批注前保存稳定内容锚点，展示一个返回入口；更换字号或屏幕宽度后仍返回同一段文字。借鉴它的返回路径，而非只增加更多跳转按钮。
3. **AI 回答固定对应的原文。** 发送时冻结选文、书名、章节与位置，回答迟到时仍指向原来源；可取消，保存前由用户决定。以后支持追问时，也应避免翻页悄悄改变旧问题上下文。
4. **常用设置就近，低频选项收起。** 主题、字号、行距可在书内设置；字体导入、接口地址、密钥留在明确设置处。参考项目的可配置菜单可以借鉴，但 QReader 仍应保持选文菜单紧凑。
5. **外部工具按需衔接。** 生词 Markdown/Anki 导出、Calibre、社区分发都有价值；只有明确需要时再启用，不让它们成为阅读前置条件。

**后续优化顺序与验收标准**

| 优先级 | 建议改动 | 为什么先做 | 完成时应验证 |
| --- | --- | --- | --- |
| P0 | 书内全文搜索，结果定位后可返回原阅读点 | 直接补齐基础阅读短板，对阅读和笔记回看都有效 | EPUB/PDF 结果准确；跨章与重开定位；搜索可取消；不阻塞当前页；退出返回相同文字 |
| P0 | PDF 独立缩放与平移，提供适合宽度/整页恢复 | 当前小字、表格和图表不易读 | 画布、文字层、高亮一致；缩放不误触翻页；阅读位置保留；长 PDF 控制内存 |
| P0 | Android/iOS 真机与长书性能基线，把现有隔离验收脚本整理成可复用流程 | 桌面窄屏不能证明触摸选词、翻页和音频实际可用 | 第一页到第二页、跨章、连续反向、快速切书、听读跟随；P50/P95、掉帧和内存均有记录 |
| P0 | 在可用 Obsidian 版本使用 SecretStorage，兼容旧配置 | 参考项目已有成熟的密钥与设置分离 | 迁移成功后不再写原明文；无该接口时有明确兼容策略；切换服务不丢密钥 |
| P1 | 缓存转换结果和位置索引，按原文件内容/版本失效 | 首屏索引等待已解决，大书仍可能反复转换 | 文件变更自动失效；不改原书；关闭可取消；缓存大小可控；旧 CFI 与笔记回跳不漂移 |
| P1 | 字体导入、宽屏双页，以及临时跳转统一返回 | 补舒适度，兼顾大屏与精读 | 缺字回退；字体不阻塞首屏；单/双页切换与重排保持锚点；窄屏控件不溢出 |
| P1 | 改进查词上下文，允许主动保留原句或导出生词 | 保留“越读越熟”的现有流程，同时满足想留少量词汇的人 | 词典先显示；AI 补充可取消；已删除词不被迟到回复加回；出现计数与去重仍准确 |
| P2 | 轻量流式解释与一两轮追问、来源回跳；再按需求接入 Calibre/Anki | 先改善等待与理解，不先扩大配置面 | 原文来源固定；接口故障可重试；保存可控；旧草稿、笔记和阅读位置不被覆盖 |
| P2 | 社区插件申请、少量公版演示书或首次使用引导 | 降低安装和开始阅读的成本 | 演示内容与用户书库分开；可跳过；卸载/升级不影响个人数据 |

具体目标应按设备与书籍类型分组。可在固定桌面基准机上先对本次 EPUB/MOBI 样本设定“开书 P50 不超过 250ms、P95 不超过 500ms”的回归目标；这是建议门槛，三次数据不足以证明 P95。大型图片书和手机要单独建立基线，不承诺所有文件一律 200ms。

全面切换 Foliate 应等独立试验确认旧 CFI、选区、高亮、听书句子锚点与转换书的定位兼容后再决定。本轮保留 EPUB.js 定位，已取得明显收益，暂时没有必要为一致架构迁移用户记录。

**QReader 可以比它进一步做好的地方**

- **听读之间切换更自然。** 现有自动返回朗读页已能区分临时浏览和停止。继续做好真机音频、断网恢复、选文起读、返回声音位置和切书释放，形成可验证的连续体验。锁屏/后台播放另行测试后再承诺。
- **词汇帮助随阅读变少。** 保留有效出现计数、去重和可解释的淡化；让读者知道为何还高亮、何时移除。若加收藏或导出，把它设为主动操作，与当前书自动淡化分开。效果需要用户长期阅读验证，不宣称已有学习成效数据。
- **笔记可以放心自由改。** 强化合并冲突的解释、原文回跳和手工修改保护，让生成的摘抄与自己的想法长期共存。两边同时改、删除批注、外部编辑、重启和同步冲突都应有可靠验收。
- **速度包含慢设备和异常情况。** 不只追求某一本书的开书数字，还要确保第一到第二页、跨章、失败重试、连续操作、退出释放都流畅可预测；将大书与手机的长尾数据纳入发布检查。
- **AI 更克制、来源更清楚。** 默认仍专注读书，遇到困难再求助。显示本次使用的选文与上下文范围、接口来源和保存状态，让“自己的笔记”与“AI 解释”清楚区分。

建议的下一批工作是：**书内搜索与返回 → PDF 缩放 → 真机与长书基线 → 密钥迁移**。随后再做缓存、字体和查词上下文。这些改动能补上当前最影响阅读的差距，同时保留 QReader 已有的听读、生词淡化与自由笔记方向。
